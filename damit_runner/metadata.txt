description=Dam breach model runs (Processing provider damit_run): damit_run:rundam accepts a DamIT Screener hand-off package (or equivalent parameters), validates it against DamIT Catalog (NID dams only: the dam needs its NID ID unless new / proposed or a desk sample), prepares the run and launches the breach model with the DamSafety Runner's parameters and defaults (breach hydrograph, LISFLOOD-FP executable or the built-in engine when none is installed, optional ANUGA tier on the DamSafety mesh, growth loop and grid refinement), writing Depth (Max), Velocity (Max), Arrival Time, WSE (Max), hmax and the flood polygons into the dam folder for DamIT Hazard.
about=Generalized from the DamSafety Runner breach-run workflow for the DamIT presets. Tools: damit_run:rundam (DRY_RUN on = prepare / record only; HEC-RAS is refused) and damit_run:checkhandoff. It never starts HEC-RAS, Wine, ndbreach:rundam or ndbreach:batch, and always creates a new run folder rather than writing into an existing one. Also ships the flood package (breach hydrographs, built-in LISFLOOD-FP and finite-volume engines) used by DamIT Screener. Classification of finished rasters is DamIT Hazard's job (damit:classify); the Runner attaches catalog metadata only. Suggested classifications only; the engineer of record and the regulating agency make the determination.

changelog=0.3.0 - an empty LISFLOOD_EXE looks for LISFLOOD-FP in the provider settings (new DAMIT_RUN_LISFLOOD_EXE / DAMIT_RUN_USE_BUILTIN, then the ND Breach Runner's NDBREACH_LISFLOOD_EXE, read only), NDBREACH_LISFLOOD, PATH and the usual install places, and when none is found runs the built-in engine with a clear warning, as the old ND Breach Runner did (a named path that does not exist is still an error); the engine used and why is in run_report.json / run_setup.json engine_selection and the new outputs ENGINE_FALLBACK and ENGINE_NOTE. The ANUGA tier uses the DamSafety Runner's default mesh (ported from DWR_Plugins main: flood mask + buffer outline, refined near field, inlet at least 3 cells, one wider second pass when the flood reaches the mesh edge); the simplified rectangle / octagon mesh is removed. The flood package gains the Screener's LISFLOOD-FP adapter and the USGS 3DEP clip download for larger screening clips. DWR-2801 real-engine fixes: OUTFLOW_EXTEND_PCT is now used as in the DamSafety Runner (once that share of the breach volume has left through the edges, every edge carrying at least 10% of the outflow and wet past the arrival depth moves out too, even under EDGE_TOL_FT; a clock extension is not counted as a run; a warning when 5% or more left in the last run); the pass records give over_outflow, boundary_outflow_pct and clock_extension. The DamSafety Screening breach-direction estimate (breach_dir.py) is vendored for the Screener.
    0.2.0 - rundam launches the model like the DamSafety Runner (ndbreach:rundam): its parameter set and defaults (METHOD piping Froehlich 2008, TIER LISFLOOD-FP only, CELL 10 m, GRID_REFINE, MANNING 0.06, growth loop LENGTH 4 / HALF_WIDTH 1 / STEP 3 / MAX_EXTENT 20 mi, MAX_RUNS 6, DURATION_MAX 96 h, ANUGA settings, PIPE_FRACTION 0.5, PIPE_DIA 0.5 ft, ...); sunny day from the top of dam with no outlet or spillway flow; toe inflow searched 5 m to H x (DS slope + 1) (3:1 default, 150 m cap, side check); writes Depth (Max), Velocity (Max), Arrival Time, WSE (Max), hmax_ft and depth / extent / arrival polygons into the dam folder; DRY_RUN now defaults off; HEC-RAS still refused. New flood package (shared with DamIT Screener).
    0.1.0 - first release: provider damit_run; rundam prepares and records a run from a damit.handoff v1 package (no model launch); checkhandoff.
