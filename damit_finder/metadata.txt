about=Seven Processing tools (Processing Toolbox > DamIT Finder > Find structures). Fills across streams and draws: walks the 3DHP / NHD flowlines and every draw traced from the DEM itself over a bare-earth DEM and reports every fill that blocks the valley (spill level, height, head, storage, pool), as a dam, dry embankment or road fill. Ponds and dugouts: classes every polygon of a water-body layer from the LiDAR. Crossings: every road / rail x stream crossing, the places a culvert or bridge must be. Open water: pond outlines from 4-band or colour-infrared aerial imagery (NDWI; several years keep the persistent water) or straight from a classified LiDAR point cloud (ASPRS class 9), marked when no water-body layer has them. Build the water mosaic: turn a folder of classified LiDAR tiles into the class-9 water-count / mean-elevation rasters (CONUS Albers, the whole U.S.) the open-water tool reads. Also: where each pool spills, dug pits and raised ridges (levees, dikes) anywhere in the DEM, the drainage area and expected pipe size at each crossing, dams / dikes / culverts from OpenStreetMap, and a score learned from the fills already on a dam list. Every candidate is checked against the known-structure layers you give (NID, state lists, NBI, DOT culverts, USGS / SARP crossings): listed, unsure or new. Runs no flood model. Candidates for review against an aerial image, not determinations; a new dam has no NID ID, so DamIT Screener does not take it as a dam record until it is listed.

changelog=0.4.2 - new optional tool 'Build a class-9 water mosaic from LiDAR tiles' (damit_find:water_mosaic): turns a folder of classified LiDAR tiles (.las/.laz) into the water_count.vrt and water_elev.vrt that 'Find open water' reads with its WATER_RASTER input - the scalable path (build once, then the open-water tool reads the mosaic a spatial tile at a time; the raw statewide point cloud is terabytes). Per tile a water-count GeoTIFF (class-9 points per cell) and a mean-elevation GeoTIFF (the pond water surface); every tile snaps to one global grid so the VRT has no seams; dry land and the gaps between tiles read back as no water. Output CRS is CONUS Albers (EPSG:5070) for the whole U.S. (the DamSafety build uses North Dakota's UTM 14N). Reuses core/lidar, launches no outside process; verified end to end (a real compressed LAZ -> the mosaic -> the open-water tool finds the pond). 0.4.1 - the open-water tool can read water straight from a classified LiDAR point cloud (.las/.laz) instead of aerial imagery: a cell is water when the cloud classes it so (ASPRS class 9), so there is no NDWI threshold, sun angle, shadow or imagery year to guess at - the classification is already made (USGS 3DEP delivers classified LAZ). Give one tile (LAS) or a folder (LAS_DIR); LAS_CLASSES (water classes, default 9), LAS_EPSG (tile CRS only when the file carries none), LAS_MIN_PTS. core/lidar.py reads with laspy if installed (LAS and LAZ), else a small pure-numpy reader for uncompressed LAS (so the class filter and rasteriser are unit-tested without laspy or GDAL); it launches no outside process. It can also read a prebuilt class-9 water-count raster / VRT (WATER_RASTER): a cell is water where the count is at least WATER_COUNT_MIN - the scalable path (feed the statewide class-9 water mosaic) when reading the raw LiDAR statewide is too much. 0.4.0 - three Wells-review follow-ups: finds a dike that holds water running beside a stream or draw (a dam built along a channel, not across it; on by default); the downstream toe carries past a bench on the face to the outlet channel, so the height is read at the foot not off a shelf (Absaraka 27.4 ft vs 27.5 listed, was ~21); the open-water tool drops cast shadows (a green-brightness test) and, with a buildings/streets layer, roofs, pavement and in-town pools. 0.3.0 - a fill on no road / rail layer whose raised ground runs on 600 m or more is a new kind, long fill (road, rail, canal or levee), not a dam (Wells County aerial review, 2026-11-12: canal banks and a divided highway missing from the road layers were the top "dams"); ridge_len_ft column and score input (a 0.2 model still scores). 0.2.0 - first release (versioned with the DamIT suite): damit_find:embankments, damit_find:ponds, damit_find:crossings, damit_find:water (open water in 4-band / colour-infrared aerial imagery, one or several years), damit_find:osm (dams / dikes / culverts from OpenStreetMap), damit_find:score (a fill score learned from listed dams); fills on draws traced from the DEM, spillways, dug pits and raised ridges, NWI codes and dugout shape, drainage area and pipe size at crossings; listed / unsure / new against the known-structure layers; review hillshade. Review fixes (2026-11-11): a DEM recording no elevation unit is refused until Metres or Feet is chosen (USGS 3DEP files = metres; warning when the ground is outside ND); Cancel stops within the tile and fails with 'Cancelled' (crossings too); screening_dams holds no road fill; a run_info table (tool, version, GDAL, time, settings) in each output; shorter check-box labels; help text names no DamSafety plugin.
