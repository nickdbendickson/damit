# Heim knowledge pack

Extra data for **Heim** (the local code-triage AI) beyond the suite source code. Heim's
RAG already indexes the repos' code and markdown; this folder adds the knowledge Heim
*can't* get from the source:

| File | What it is |
|------|-----------|
| `KNOWN-BEHAVIOURS.md` | Standing conventions, durable known behaviours/bugs, cross-plugin hand-off contracts, and Processing-provider gotchas. |
| `MODELING-FINDINGS.md` | Empirical run findings (grid convergence, solver comparison, velocity sensitivity, mass balance) — the "why" behind results-changing fixes. |
| `OPEN-ISSUES.md` | Snapshot of open GitHub issues (regenerate with `refresh-open-issues.zsh`). |
| `ALGORITHM-HELP-DAMIT.md` | The REAL DamIT Processing algorithm ids, parameters and defaults, generated from the plugin code by `tools/dump_damit_algorithm_help.py` (offscreen QGIS; CI checks it is current). Heim cites ids from here. |
| `WATCHER-DIGEST.md` | The run watcher: what the deterministic digest checks, every flag id, the hooks, and who decides the verdict (code, never Heim). |
| `ALGORITHM-HELP.md` + `algorithm-help/` | The DamSafety Processing tools (`nddam`, `ndbreach`, `ndhazard`, `ndfind`, `ndpmp`, `ndlite`): the list of every algorithm id, and one page per tool with its parameters, defaults and description, GENERATED by `dump-algorithm-help.zsh` from `qgis_process help`. One page per tool because the indexer skips any text file over 256 KB and all of them together are about 800 KB. |
| `FAILURE-CASEBOOK.md` | Real failures of the suite as symptom, cause, how to tell, fix: wrong results with no error, things that only look stuck, installer deaths, and the local AIs' own failures. |
| `FILE-CONTRACTS.md` | The state files passed between stages (`dam.json`, `_chain_nd/state.json`, the review runs' `status/*.ok` and `rundam.json`, `run_progress.json`, `stable_settings.json`, the AI stores): who writes, who reads, what makes each stale. |
| `RUN-RECIPES.md` | How runs are launched (`damchain`, `run_nickreview.sh`, `use_local_terrain.sh`, the batch scripts, the watcher, Vor), where results and logs go, what a second run skips, and the environment variables that change a run without appearing on its command line. |
| `CLI-HELP.md` | Every flag of the local-AI tools, GENERATED from their argument parsers by `tools/dump_cli_help.py` (CI checks it is current). Heim cites flags from here. |

There is also a **code-triage eval** in [`../eval/questions.json`](../eval/questions.json), run with
[`../tools/eval_heim.py`](../tools/eval_heim.py): 21 questions whose answers live in this pack, scored
against a model so you can measure Heim's triage quality and catch regressions when you change models
(`python3 eval_heim.py --model <tag>`). It mirrors the Vor eval.

The per-plugin fix log stays where it already is — each plugin's `metadata.txt` `changelog=`
(and `docs/CHANGELOG.md`) — which Heim already indexes. This pack does not duplicate it.

## Index it into Heim

```
cd damit_ai/heim/knowledge
./index-knowledge.zsh                    # -> collection "heim_knowledge"
./index-knowledge.zsh --with-engine-docs # also the Vor engine docs, if downloaded
```

`rag_query` searches `all` collections by default, so once indexed Heim cites these
automatically. Ask e.g. `heim "what does REFINE_NEAR do and why is it off by default"` or
`heim "has the 2801 over-spread been attributed to the solver or the terrain"`.

## Keep it current

- `python3 ../tools/dump_damit_algorithm_help.py` (QGIS Python, `QT_QPA_PLATFORM=offscreen`) regenerates
  `ALGORITHM-HELP-DAMIT.md`; add `--check` to see whether it is stale. Run it whenever an algorithm or parameter changes.

- `python3 ../tools/dump_cli_help.py` regenerates `CLI-HELP.md` (plain Python, no QGIS, no Ollama);
  `--check` says whether it is stale. Run it whenever a tool gains or loses a flag.

- `heim-doctor` says when this pack's index is older than its files, or holds a file too big to index.

- `refresh-open-issues.zsh [owner/repo ...]` — re-snapshot open issues (needs `gh`).
- `dump-algorithm-help.zsh [profile]` — re-dump the DamSafety tool help into `ALGORITHM-HELP.md` and
  `algorithm-help/` (run on a machine with the plugins installed in a QGIS profile, and give the profile
  name). The plugins live in the DamSafety repository, so no check in this one can tell when these pages
  fall behind: re-run it when a DamSafety tool gains, loses or renames a parameter.
- Edit the curated `.md` files (`KNOWN-BEHAVIOURS`, `MODELING-FINDINGS`, `FAILURE-CASEBOOK`,
  `FILE-CONTRACTS`, `RUN-RECIPES`) by hand when a decision or durable behaviour changes.
  Keep machine names, credentials and file-server links out of them.
