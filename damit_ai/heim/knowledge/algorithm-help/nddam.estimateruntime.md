12 - Estimate the run time of the simulations (nddam:estimateruntime)

----------------
Description
----------------
ORDER-OF-MAGNITUDE estimate of how long tool 7 will take for these dams, before you start it. For every dam it works out what tool 7 would start with - the automatic cell size (by storage, >= 2 cells across the breach), the tool-2 clip (its half-width from the cached DEM when the folder is given, else 1,500 m), the corridor along the flow path, the run length from the hydrograph and the path - then the number of time steps (CFL limit at a representative depth) and the time from a tiny CALIBRATION RUN of the built-in engine on a 60 x 60 synthetic grid on this computer (a second or two). LISFLOOD-FP: the same count times a factor you set (default 0.1, i.e. ten times faster: a GUESS until you time it here).
Low = one run per dam; typical = two; high = four (tool 7 re-runs a dam when the flood reaches the corridor wall or the terrain edge or is still spreading). Reality is usually within a factor of about 3 of 'typical'. Not counted: cascades, 3DEP downloads, other programs using the CPU.
Output: a CSV with one row per dam (cell size, cells, steps, low / typical / high seconds) and the totals in the log. Dams cleared by triage are skipped as tool 7 would skip them. Not run in a real QGIS during development (test doubles only).
