8 - Hazard classification (nddam:hazardclassification)

----------------
Description
----------------
Overlays the flood rasters on what ND Dam Safety Standards REG_05.2026 Sections 5.2 / 5.3 list and classifies each dam with core/nd_hazard.py - the same module, byte for byte, as ND Dam Breach Runner, sampled the same way, so both plugins give a dam the same class from the same flood.
CHECKED: habitable structures (5.2.1.1), roads (5.2.1.2), railroads (5.2.1.3), lifeline facilities (5.2.2) and the other dams of the input layer that this dam's flood reaches (5.3 cascading). HIGH: potentially lethal to occupants of a habitable structure; interstate or AADT > 2,000; >= 10 trains a day or an active passenger line; a High dam reached downstream. MEDIUM: a habitable structure inundated at any depth (economic loss); a US / State highway (5.2.1.2(b), any AADT), AADT 500-2,000 or sole access to an occupied location; any other railroad; a lifeline facility inundated; a Medium (or unclassified) dam reached. LOW: only uninhabited buildings, private or AADT < 500 local / county roads, or nothing of these is reached. A habitable structure in the charts' judgment zone is MEDIUM by rule (not potentially lethal). Borderline results take the higher class (5.3): an unknown velocity counts as potentially lethal (hz_border = yes when every governing finding is borderline or rests on an assumption).
LETHALITY (default): the ACER TM 11 depth-velocity charts (ND Fig. 5.1 houses, 5.2 mobile homes) - they must be digitized and checked first; the chart file shipped is NOT, so this method stops with a message until then. Until then use the conservative 'every inundated habitable structure' method. The 2 ft rule is allowed only for 1D models (5.2.1.1) and these floods are 2D. COMPARISON ONLY, not the ND authority: FEMA/Feinberg thresholds (DSS-WISE HCOM) and your own curve CSV (velocity_ms,depth_m).
SAMPLING (as the runner): points - the cell under the point; polygons - the deepest cell whose centre is inside each part's exterior ring (the cell under the centroid when none is), with the largest velocity over the wet cells; lines - every half cell, the deepest. Multi-part features use their deepest part with the largest velocity over their wet parts / points (TM 11 practice: peak depth with peak velocity, even from different cells); DV (Feinberg) = that peak depth x peak wet velocity, never a DV raster. Rasters are m and m/s, converted to ft and ft/s. ANY DEPTH: from 0.03048 m (0.1 ft, the runner's WET_FT).
HABITABLE: a tool-0 'habitable' yes/no field wins; otherwise every structure is habitable unless its occupancy texts name an uninhabited building (the editable word list: barn, shed, garage, silo, grain bin, outbuilding, well pad …). Mobile homes (Fig. 5.2): 'mobile' / 'manufactured' / 'trailer' / NSI RES2. ROADS: a missing, zero or NaN AADT is unknown - the 'unknown AADT' class you choose (default Medium), listed in hz_gaps; interstate from I-94 / I 94 / IH-29 / 'Interstate' / TIGER 'I'. Same for a railroad without a train count.
OUTPUT: hz_class, hz_basis (method), hz_border, hz_gaps, hz_chart (chart status and the first 12 characters of the chart file's SHA-256). Dams cleared by triage are LOW (hz_conf = triage). For audited dams, 'audit' says whether the 2D model agreed. Screening only: the official classification is the Department's.
DAM RECORDS (optional, v0.9): with a Dams folder, every dam that already has a folder there (<Dams folder>/<dam ID>/, e.g. made by tool 7b or ND Dam Hazard) gets a 'screened' status in its dam.json (the suite's shared dam record): the triage result (clear / needs 2D / not run), hz_class, hz_border and hz_gaps, plus the dam's ID, name, NID ID, DWR number, height and existing class where the record has none. No folder is created; a value another tool wrote is never overwritten.
INCREMENTAL (v0.11, off by default): with tool 7's no-breach baseline (BASELINE), structures, roads, railroads and lifelines count as inundated by the breach only where the INCREMENTAL depth (<dam>_<scenario>_incr_depth.tif = breach depth - no-breach baseline depth) meets the depth threshold; the velocity (and depth x velocity) still come from the breach run. hz_basis says 'incremental vs no-breach baseline (ambient X cfs)'; a dam without the baseline raster is classified from the breach flood and gets a data gap. A screening approximation of ND's flood-scenario comparison (the real design-flood routing is the Runner's / the engineer's); the 5.3 check of other dams reached uses the same incremental depth.
