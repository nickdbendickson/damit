7b - Detailed runs with DamSafety Runner (nddam:runnerhandoff)

----------------
Description
----------------
Sends the dams that matter to the ND Dam Breach Runner plugin (v3.1 or later, provider 'ndbreach'; install it first) for a defensible breach flood and its ND 5.2 classification, one dam after the other, and puts the runner's class next to the screening class.
For each chosen dam: 'ndbreach:rundam' with the dam ID, the tool-4 breach point as the dam point, height (ft, from height_m), storage at the top of dam (ac-ft, from tool 5 td_vw_m3, else tool 3, else the inventory maximum), the surface area near the top of dam from the tool-3 curve when a curve folder is given (0.17.46: when the dam's curve is too shallow, missing or gives no area - and 0.17.49: when no curve folder is given - the DWR inventory's maximum-pool area instead - tool 1's inv_maxa_m2, from max_pool_area in acres - with a warning; no inventory area = none sent, also with a warning; the normal-pool area inv_area_m2 is never sent), your DEM and Dams folder. No DWR elevations are passed (local datum): the runner takes the top of dam from the DEM. Breach hydrograph: the runner's own ND method (default), or the screening's tool-5 hydrograph written to <Dams folder>/<dam>/inputs/breach_hydrograph.csv (hr, cfs) and passed as the runner's own-hydrograph CSV. Then 'ndbreach:ndhazardclass' on the dam folder with your receptor layers, the dams layer as downstream dams (5.3 cascading: D_ID = dam_id, D_CLASS = the existing class field), the uninhabited-building words, 'any depth' (WET_FT) and the unknown AADT / trains classes, and its JSON is read back. In 'High and Medium' mode dams without a screening class (NoData or empty: failed simulation) are sent too.
Both plugins use the same rules module (core/nd_hazard.py, ND 5.2 / 5.3 with the ACER TM 11 charts); the chart method needs digitized and checked charts.
RUNNER MODELS (ENGINE, FORCE_ANUGA, REFINE_NEAR, CULVERTS): left at their defaults nothing extra is sent and the Runner runs LISFLOOD-FP only. 'Runner models' = LISFLOOD-FP for the extent, then ANUGA sends TIER=1 (final results from ANUGA). 'Force ANUGA' asks for ANUGA final results even when 'Runner models' is LISFLOOD-FP only (the Runner needs ANUGA set up). 'Near-dam refine' re-runs the area next to the dam with the FV1 solver. CULVERTS (lines, upstream end first) go to the Runner's STRUCTURES and are used only by ANUGA: with LISFLOOD-FP only and force ANUGA off they are logged as not used. The C_* fields name the culvert layer's columns; empty = the Runner matches its synonyms (kind, width_ft, height_ft, barrels, shape, name).
OUTPUT: the input dams plus rn_status (done / failed: message / skipped: reason), rn_folder, rn_class, rn_border, rn_gaps, scr_class (the screening class, hz_class), rn_agree (agree / runner higher / runner lower), rn_inputs (what was sent) and rn_area_src (0.17.46: where the surface area came from - stage_storage, inventory_max_pool_area or none; also in dam.json's source note, the log and the run manifest as surface_area_source). A dam that fails is logged and the others continue. Runner runs take minutes to hours per dam; the runner needs LISFLOOD-FP set up in its own provider settings.
DAM RECORD (v0.9): before each run, <Dams folder>/<dam ID>/dam.json (the suite's shared dam record) gets the values sent to the runner - dam_id, name, nid_id, DWR structure number, height, storage, surface area, the breach point (lon / lat and EPSG:5070 x / y), existing class - and a 'screened' status with the triage result (clear / needs 2D), tool 8's class, borderline flag and data gaps. A value another tool or the engineer put there is never overwritten (the conflict is logged and kept in the file). The tool stops when an installed ND Dam Breach Runner is older than this plugin needs (suite version check).
RUNNER DEM SOURCE (0.17.55): with no DEM loaded, 'Runner DEM source' can download one for the chosen dams: the box around their breach points (after 'Dams to send') plus 'DEM download buffer (mi)' (default 10 mi = half the Runner's largest domain side). The 10 m choice writes one USGS 3DEP GeoTIFF in EPSG:5070 (metres); the 1 m choice downloads the native 10 km lidar tiles from The National Map into the suite's shared tile folder (resumed, never the data pack) and builds a VRT over them. Files go to 'Folder for the downloaded DEM' (empty = <Dams folder>/_runner_dem) and are reused on the next run for the same dams. The request count and size are logged first; a download over 'Largest DEM download for one run (GB)' is refused before anything is fetched. The downloaded DEM is sent with the Runner's 'DEM elevation units' set to Meters.
WATER-BODY MASK (0.17.46, advanced; Runner 3.10.27 or later): the Runner's run report can give the flooded area and speeds with and without the lakes and ponds that were already there (rundam WATER_MASK). It changes the report only, never the flood model, its rasters or the class. 'Runner's default' (the default) sends nothing; 'Off' sends off; 'Use the water-body layer below' sends that layer's file (it must be saved in a file; a temporary layer stops the tool). An older Runner is warned about and gets nothing.
RUNNER ENGINE (0.17.22): one choice. 'LISFLOOD-FP only' (the Runner's default; TIER 0) is the fast local-inertial 2D model. 'LISFLOOD-FP for the extent, then ANUGA' (TIER 1) uses LISFLOOD-FP to find how far the flood goes and re-runs it with ANUGA (unstructured mesh) for the final results; it is much slower and needs the Runner's ANUGA environment (checked before any dam is run). This is what the old 'force ANUGA' box did; an old FORCE_ANUGA = True still selects it. The engine used is logged as a warning when it is ANUGA and written to rn_engine. 'LISFLOOD-FP then HEC-RAS 2D' (TIER 2, optional) builds and runs a HEC-RAS 6.6 2D model after LISFLOOD-FP (subgrid terrain from the DEM, the breach hydrograph at the inflow point, culverts / bridges as SA/2D connections) and writes its maxima as the final rasters; it needs the Runner's HEC-RAS set-up (NDBREACH_HECRAS_WINEPREFIX, NDBREACH_HECRAS_LINUX_DIR; checked before any dam is run) and HEC's Terms and Conditions accepted by the user.
NEAR-DAM REFINE: re-runs the stretch next to the dam on a finer grid with the FV1 solver (full shallow-water equations, more accurate for the fast, steep flow near a breach) and merges it in; adds roughly the time of one more model run.
CULVERTS / BRIDGES (CULVERTS): lines drawn from the UPSTREAM end to the downstream end (the first vertex is the inlet). Fields (empty = the Runner's synonyms): kind (culvert / bridge / notch), span or diameter (ft), rise (ft), barrels (count), shape (box / pipe), name. Only ANUGA models them; with 'LISFLOOD-FP only' the layer is ignored and a warning says so.
